# ADR-049: Place suggestions come from Google Maps through a capped anonymous proxy

- **Status:** Accepted
- **Date:** 2026-11-18
- **Related:** ADR-011, ADR-029, ADR-043, ADR-045, ADR-048; tracker #150
- **Plan:** `~/projects/beanies-ops/docs/plans/2026-11-18-location-autofill-and-link-150.md`
- **Spike:** `~/projects/beanies-ops/docs/research/2026-11-18-place-search-providers.md`
- **Operations:** `~/projects/beanies-ops/docs/runbooks/place-search.md`
- **Implementation:** Built behind the `placeSuggestions` flag (committed off). Nothing here is live until flag day.

## Context

Location fields were plain text boxes. A member typing an address got no help, the map link searched whatever text was typed, and the unit or room detail that address autocomplete normally drops had nowhere to live. #150 adds suggestions while typing, keeps the member's own unit or room detail on its own line, and makes the map link open the exact place. Suggestions need a third-party places service with a secret, billable key, so the key cannot ship in the client, and the app is local-first with no server that sees family content (ADR-011, ADR-029). Typed text is the member's own words and can be an address, so the design has to say exactly what leaves the device.

## Decision

1. **Provider: Google Maps Platform (Places API (New) Autocomplete, and Geocoding on pick), behind an adapter.** A three-provider spike on one fixed list of ten addresses (including a Singapore block-and-unit example, US and London addresses, and a Japanese address) decided it. OpenStreetMap (Photon, and so Geoapify, which serves the same data) found 5 of 10: it did not know ordinary Singapore street numbers, which is the feature's headline case. Apple Maps found the right place first for 10 of 10, but the Apple licence (Attachment 6, 2.4) requires an Apple map to be shown with any address result and (2.5) forbids storing Map Data beyond a temporary basis; #150 shows a map-less list and stores the place. Google found the right building for 10 of 10 (two unit-heavy inputs only after a trimmed retry). The Lambda owns the provider: `providers/google.mjs` maps Google's answers to the beanies `{ placeId, main, secondary }` and `{ placeId, address }` shapes, so a provider change is a server change plus attribution and wording.
2. **The proxy posture is ADR-045's.** Anonymous: a request carries the typed text, a language and an optional rounded bias point, never a family id, member, token or client IP. A soft `x-api-key` (it ships in the bundle, so it is weak authentication, the same as flight-status), a route throttle, reserved concurrency, a per-IP limit of **60 an hour** (flight-status's 240 would let one address spend most of a day's cap), and **global daily caps: suggest 650, resolve 320** (Terraform variables `daily_suggest_cap`, `daily_resolve_cap`). The caps fail **closed**: a counter-store fault, or an unset table, refuses with `budget_unavailable`; an unset table must never mean "no cap". The per-IP counter fails open. The Lambda builds both Google requests itself (a fixed field mask, a 50 km bias circle, a region code) and relays nothing else; `q` is refused when it contains `://`, an `@host.tld` or a line break, so a link or an email never reaches Google from any client. Suggest returns at most five results of at most 200 characters. There is no server cache (Places content may not be cached). **Accepted residual:** anyone who reads the bundle holds the soft key and can spend a day's cap in about a minute; the result is quiet fields until 00:00 UTC and a bill bounded by the caps. The console's per-day quota is a fixed backstop of 1,000 a day per API, deliberately not equal to the Lambda caps; a $1 budget alert is detection only.
3. **Data model: the legacy string stays the source of truth.** `location` / `address` / `agencyAddress` keep holding readable text. A picked place is an optional sibling `PlaceRef { placeId, name }` (`locationPlace`, `addressPlace`, `agencyAddressPlace`), a value object always written whole, never merged per key (a test pins that none is in `MERGE_FIELDS`). It is honoured only by the prefix rule `validPlace(text, place)`: the place counts only when the string equals `name` or starts with `name + ', '`. **That rule is the merge-safety mechanism**, not a nicety: the string and its place are two independent last-writer-wins registers, so two devices picking different places can leave one device's string beside the other's place, and `validPlace` makes that harmless (the place is ignored and the member sees their text with a search link). Every reader goes through `validPlace` (a grep test enforces it). The **kept detail is not stored separately**: it is the rest of the string after `name + ', '`. **Links are derived, never stored**: whether text holds a call, a web link or a map link is worked out at render time by one pure function, so nothing about links is persisted and nothing goes stale. **No provider marker is stored on a place:** absent means Google, and a later provider change adds an optional `provider` key and never reinterprets old IDs.
4. **Storage terms.** The place ID may be stored indefinitely under the Places terms. The place line, Google's `formatted_address` fetched with one Geocoding call on pick, is stored in the family's own data under Geocoding terms 6.3.2, which allow indefinite caching for the end-user feature that asked. The clause says "isolated to the specific End User"; a family-shared activity is a reading greg accepted on 2026-11-18. The suggestion text and coordinates are never stored. Attribution is the text "Google Maps" in the suggestion list, not "powered by Google" and not translated.
5. **What is never logged.** Client and Lambda log counts, outcomes and timings only: never the typed text, a place ID, a place name or an address, a header, a key or an IP. No new telemetry context key was added. The Lambda parses provider answers itself and maps a parse failure to `upstream_http`, because Node's parse error message quotes the body; a test asserts no log line contains the key, `q`, a place ID or a provider body on any error path.
6. **Kept-detail rule.** `splitKeptDetail(typed, { carried, main })` returns what the member typed that the SAVED place line does not carry, in original order and spelling, and keeps more when unsure. `carried` is what is stored (Google's formatted address); `main` is the picked suggestion's main text, used only to recognise a half-typed word. Words are compared **in order** (an alignment, never a bag of words), and abbreviations fold only against the address's street line (the part before the first comma, plus any leading sub-premise part such as the `flat 2` of `flat 2, 221B Baker St, London`) and against `main`; city, state, postcode and country compare exactly, so `court` never meets `CT` and `northeast` never meets `NE`. The typed text splits on whitespace into chunks. (1) The **tail** starts at the first chunk that is a sub-premise keyword (block, blk, unit, apt, suite, level, floor, fl, room, flat) or starts with `#`, provided an earlier chunk is not a keyword (`unit 04-19, 127 south bridge road` has no tail). (2) The **head** (the chunks before it) is aligned in order against the address, ties going to the later typed words; a head chunk is dropped only when every word of it aligned (`raffles place tower 1` keeps `tower 1` against `1 Raffles Pl`). (3) The tail is decided **whole**: dropped only when every one of its words aligns in order with address words the head did not use (`1 Raffles Place #20-61 Tower 2` against `1 Raffles Pl, #20 61 tower 2, ...` leaves nothing), otherwise kept verbatim (`12 Main St unit E` keeps `unit E` against `12 E Main St`). (4) With no tail, a head chunk the address does not carry whose word is only a strict prefix (two or more letters, and only the last typed word) of the next word of `main` is a half-typed **fragment** and is dropped (`127 s brid` leaves nothing, `marina bay sa` keeps `marina bay`); every other head chunk the address does not carry is kept (`Marina Bay Sands` against `10 Bayfront Ave`, `west wing`, `PH`, `B`). (5) A keyword or wordless head chunk is kept only if the chunk after it is kept, so `Blk 293 Yishun Street 22 #05-12` keeps `#05-12`, not `Blk #05-12`. **Change rule: the function is changed only for a case where typed text was lost or a half-typed fragment was kept.** A case that keeps too much is not a bug, because the detail line is editable and "Keep what I typed" exists. The abbreviation table holds the short forms Google's formatted address uses (directions, road types, `jalan`/`jln`, `lorong`/`lor`, `mount`/`mt`); no per-locale tables, and a missing pair only keeps a stray word. Two guards close the loss cases found in review: the tail is dropped only when it is two or more words that align as one unbroken run of the address (a lone `#4` is never spent on the house number of `4 Main St`), and only the **last** typed word can be a fragment (`west wing` against main `Westfield Sydney` keeps both words). **Known residuals, by design:** `Blk 5 unit 3` against an address carrying `5` keeps `unit 3` (the block number is in the address); `12 Main St Springfield Mall` keeps `Mall` because Springfield is in the address.
7. **Two link-acceptance rules, and call services as data.** A span of text is a link only when (a) it had an explicit `http(s)://` scheme, or (b) it is a bare host that starts with `www.` or matches the call-service or Maps host list. Any other bare `word.word`, with or without a path, stays address text ("St.Regis Hotel", "Jln.Besar/Kitchener" are places). A new rule needs a failing fixture and an edit to this ADR. Call services (Zoom, Google Meet, Teams, Webex, VooV / Tencent Meeting, FaceTime and others) are exact-host data in `src/constants/callServices.ts`: a host matches when it equals an entry or ends with `.` + the entry, with no regex and no substring, so `zoom.us.evil.example` never reads as Zoom. Each entry carries its own fixture; a missing service degrades to Open Link, so the list is never urgent. Non-http schemes (`zoommtg://`) stay visible as text but never reach a map query.
8. **The trimmed retry is built, with a review date.** Two of ten spike inputs return nothing directly and succeed after one retry that keeps the words before the first sub-premise keyword (else the first five words). It counts against a six-request cap per field session. **Review at flag day + 60 days** from `place_suggest` `kind: 'retry'`: if fewer than one retry in five returns a suggestion, delete it.
9. **Sibling Lambda modules, pinned by a drift test, not a shared kit.** `place-search/http.mjs`, `ddb.mjs` and `store.mjs` restate the generic helpers of flight-status (every Lambda is its own zero-dependency zip; a shared directory would change a live paid Lambda's zip layout). `place-search/__tests__/twinDrift.test.mjs` asserts `fn.toString()` equality for each restated function, so a fix to one copy cannot miss the other. This is the third copy of the counter helpers (ai-extract, flight-status, place-search). **A fourth Lambda needing the counter helpers triggers the shared-kit decision instead of a fourth copy.** No flight-status file changed.
10. **Accepted prefix residual on concurrent picks.** A `name` may itself contain `, `. If two devices concurrently pick places where one name is a prefix of the other (`12 Main St` and `12 Main St, Springfield`), a merge can leave the longer string with the shorter place, which then reads as that place plus a detail and opens the other pick. It needs two concurrent picks on one field and is corrected by the next pick. Pinned by a test.
11. **Privacy-forward surface.** The family's saved home town (the weather one), rounded to about a kilometre, plus its country, is sent as a ranking hint; the device's own location is never read. Offline, switched off, unconfigured, capped or failed, a passive lookup is simply a plain text field with no banner. A pod manager can turn the feature off in Settings ("Address Suggestions"). The privacy page, terms page (with the Google Maps notice and links), help center and store data declarations say what is sent.
12. **Flag retirement.** The flag `placeSuggestions` is committed off. Flag day is an ordered checklist (privacy and terms pages live, store declarations approved, Lambda deployed and exercised, quota checked, then the single flip). **Thirty days after flag day with no rollback**, delete the flag, the `enabled` and `mapWhenOff` options of `describeLocation`, the legacy-control branch in `LocationField`, the two `includeMeetingUrl` booleans and the two copy branches.

## Consequences

- Google sees what a member types in a location field (3+ characters, never a link), the app language, a rounded home town with its country, and the proxy's address; never a family. Google may retain search terms under its own policy.
- The bill is bounded by the two daily caps, about $28 a month at the suggest cap if every request is billable.
- A global cap means abuse can quiet suggestions for everyone until 00:00 UTC; fields keep working as plain text. Five alarms page `#beanies-errors`.
- Older app builds ignore the sibling place and read the string unchanged, so the pod stays readable everywhere; a build that rewrites the start of the string makes the place inert.
- The Google Calendar import and view-only reads gain the event's meeting link through ordinary event fields, with no new scope (ADR-048).

## Revisit when

- Google changes its prices, free allowance or storage terms, or the console offers a per-day quota for Places API (New) that changes the backstop.
- The retry review at flag day + 60 days.
- A fourth Lambda needs the counter helpers (the shared-kit decision).
- Real requests per lookup, from `place_suggest` telemetry, differ from the spike's estimate of 2 to 4 for typing and 1 to 2 for a paste.
- A provider other than Google is wanted (adds an optional `provider` key, never reinterprets old IDs).

## Alternatives considered

- **OpenStreetMap (Photon, Geoapify).** Rejected: missed ordinary Singapore street numbers (5 of 10); a paid service uses the same data.
- **Apple Maps Server API.** Rejected on licence: an address result must be shown with an Apple map and Map Data may not be stored.
- **Storing the member's own words as the place line** (no second call, no `/resolve` route). Rejected by greg: a member who types `127 s brid` and accepts a suggestion would keep that fragment as the saved address.
- **Storing the suggestion text as the place line.** Rejected: the Places terms do not let us store it; Geocoding's `formatted_address` can be stored.
- **A stored `detail` field beside the place.** Rejected: derived from the string instead, so editing the detail writes only the string and never rewrites the place.
- **Exact-match place validity.** Rejected for the prefix rule, which survives an older build that edits the tail of the string.
- **Session tokens.** Rejected: they save nothing below 12 requests per session.
- **A shared Lambda kit now.** Deferred to the fourth user of the counter helpers (decision 9).
- **A per-family key or per-family metering on the proxy.** Rejected, as in ADR-045: it would put a family id on the wire.
