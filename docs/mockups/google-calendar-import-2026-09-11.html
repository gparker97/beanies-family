Bringing your calendar across

The one-time Google Calendar import, issue #94. A migration, not a sync: one direction, once, reviewed by the user, and then it ends. The screen that matters is step 2, because it is where a parent decides what happens to events that already exist in Google.

The one idea this flow has to land. Every row states its own outcome. An event you created gets taken over, so beanies edits update the original and Google still holds exactly one copy. An event someone else created gets copied, and beanies says plainly that your edits will stay here. A recurring event is one row with its pattern, never thirty-eight rows.

Notes for the plan. Chip wording is the part worth arguing about, since it is the whole feature in two words. "beanies takes it over" reads as ownership without saying "adopt", which means nothing to a parent. "Copied across" is honest that a second thing now exists in beanies while the Google event is untouched. The invited explainer appears in the review list and has to persist on the imported activity, so it is written as a sentence that still makes sense months later, not as a one-off warning.
