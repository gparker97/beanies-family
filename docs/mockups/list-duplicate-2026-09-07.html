Copy a list, once or for every bean

Families keep one chore list per child with the same items in each. Today the only way to make the second one is to retype it. Two directions for the copy flow below, both clamped to the CIG: Heritage Orange for every action, squircle corners, Outfit and Inter, and the semantic dark scale from packages/brand/theme.css.

1Where it lives

Copy and delete sit top-right of the tile, matching BeanCard.vue’s edit / share / delete cluster. To make room, the owner dot moves out of the tinted strip and down beside the category label. Two consequences worth naming: ListTile’s root has to stop being a <button> (no nested buttons), and it should keep keyboard focus while doing so — BeanCard’s <article @click> isn’t focusable, and copying that verbatim would regress this tile.

Choosing between them

 A · Chips, one titleB · A row per copy
New parts None. FamilyChipPicker plus one text input inside a BeanieFormModal. A repeating row component, and the chips have to stay in sync with the rows both ways.
Naming One pattern for all. A bean who needs a different name has to be renamed afterwards. Each copy named before it exists. Handles “Max’s Weekend Jobs” without a follow-up edit.
One copy Reads slightly oddly: a token in a name field for a single bean. Reads naturally. One chip on, one row, button says Create Copy.
Mobile Short. Fits without scrolling at four beans. Grows a row per bean, so a five-bean family scrolls inside the sheet.
Verdict Recommended Ships the chores case with nothing new to maintain. The {bean} token is the one idea a person has to learn, and the helper text under the field teaches it. Better product if list-copying becomes a habit rather than a setup step. Worth revisiting once there is usage to look at.
