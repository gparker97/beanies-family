Notifications — beanies.family

Mockup · 2026-05-26 · in-app notifications only (push is a later phase). Derived list + synced read-state. Shown at desktop and mobile widths.

Colour note: the brand rule (and the design-system spec for this exact element) says the unread indicator is Heritage Orange, not Alert Red — red is reserved for destructive confirmations. This mockup uses Heritage Orange throughout. If you truly want red, it's a one-token swap, but it would break the "warmth-not-alarm" rule.
Two interaction treatments below. Treatment A = bell → dropdown list → detail drawer (exactly as you described). Treatment B = bell → one drawer that slides list → detail (single primitive, identical on mobile). My recommendation is noted at Treatment B.
1 · The header bell + badge

A new squircle bell joins the existing header controls (privacy · search · profile), per the design-system header spec. Two badge styles shown: a simple unread dot (recommended — calm) and an unread count. The PWA / installed-app icon carries the same orange badge via the Badging API.

Badge clears when everything is read

The orange dot/count appears whenever ≥1 notification is unread, and is removed from the bell and the app icon the moment the last one is read (or "mark all read" is used). Because read-state syncs through the family file, clearing on your phone also clears it on your laptop.

2 · Treatment A — bell dropdown (the list) as you described

Clicking the bell opens an anchored dropdown of notification summaries, grouped by recency and styled unread-vs-read. Top-right: Mark all read. A row click opens the detail drawer (section 3).

4 · "What's new" — now a notification, not a modal

On login, if there's an unseen release, the drawer auto-opens to the What's New notification (replacing the old centre modal). The full rich content — feature cards with "Try it →", the "also fixed" list, and the signature — renders inside the drawer. It can be closed or marked unread like any other notification, and you can always re-open it from your list later.

5 · Treatment B — one drawer, list → detail my recommendation

Instead of a dropdown + a separate drawer, the bell opens a single BaseSidePanel showing the list; tapping a row slides the same drawer to the detail with a back arrow. One primitive, one mental model, and it behaves identically on mobile (where a dropdown is cramped). Left = list state, right = detail state of the same drawer.
