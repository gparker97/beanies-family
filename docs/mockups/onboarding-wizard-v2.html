Step 2 — Account

What changed

  • Now its own dedicated screen. Was section A of the old "Money" 3-in-1 step. One focus, breathable.
  • Section A header (letter badge + "drop in an account") → step's own emoji + title + Caveat sub. Same hierarchy, less stacked text.
  • Field order: easiest-to-answer first. Bank + Balance grid up top (bank name is the most top-of-mind answer about any account), then Type chips (🏦 Checking · 💰 Savings · 📈 Investment) just above the preview row so the auto-name visually responds to the chip the user just tapped. The live wizard puts chips on top — this flips the order to follow the same easy-first principle used elsewhere in onboarding.
  • Same components as production — the 2-col grid is still ob-account-grid, the chip row is still FrequencyChips with accountTypeOptions. Only the vertical order changed.
  • No manual "Account name" field. The live wizard never had one — it auto-derives the name as {owner}'s {bank} {type} ("Greg's OCBC Checking") and shows it faded at opacity 0.35 as a preview before Add. The earlier mockup added an unnecessary input; this restores the original low-friction pattern.
  • Component-faithful inputs preserved: bank picker is a BaseCombobox-style trigger (white, rounded-xl, soft shadow, with search + "Other" custom option in production), balance is a CurrencyAmountInput pair (currency pill + right-aligned amount input). Same dropdowns and styling as today.
  • Visual language preserved: cloud-white → peach gradient, corner ambient blobs, floating decorative emojis (💰 🐷 🏦), Outfit titles + Caveat sub-heroes, white shadowed form inputs with heritage-orange focus states, gradient pill add-button.
  • "Skip for now" in the bottom nav — same pattern across all 4 setup-data screens.

Step 6 — Complete

What changed

  • NEW: per-member invite section. Each row = one family member added in setup: avatar + name + email field + "Send →" button. Click Send → opens the existing ShareInviteModal (you've already polished it — WhatsApp / Telegram / SMS / Messenger / WeChat / Email / Copy + QR channel grid) pre-filled with that member's email and a pre-generated invite link via useInviteFlow. After share, row gets a "✓ Sent" badge and the email input locks.
  • Children with no email render an inline "no email — skip" hint — no Send button, doesn't block. Per the isTemporaryEmail() check or a blank-email member added in setup.
  • "✨ you can always invite anytime later from My Pod" Caveat-italic reminder — soft footer below the rows so users feel safe skipping.
  • "Skip the rest" link bypasses the whole section without finishing — same skip pattern as setup-data steps. The main "Enter the Nook 🏡" CTA works regardless of whether 0/some/all invites were sent.
  • Visual language preserved: cloud-white → peach gradient, golden ambient blob in corner, celebratory floating emoji (🎉 🫘 🌟), 110px hero mascot with float animation, summary-stat tiles, pulse-glow primary CTA, Caveat-italic sign-off line "go take care of your beans..." below the CTA.
  • Disclosure NOT needed — invite section renders inline (open) by default, since it's the natural last action on this screen. The "Optional" pill + "Skip the rest" link cover the bypass without hiding the rows.
  • Section only renders when storage is Drive AND ≥1 invitable member exists. Local-storage pods have no shareable file; lone-owner pods have nobody to invite.
