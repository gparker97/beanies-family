Read it again, and stop leaving the times blank

Two capture-quality gaps on one screen. A recipe captured from a link can be read again, with the user deciding what to keep. And prep, cook and servings stop coming back empty — the model may infer them now, provided it says so, using the same “beanies filled this in, check it” treatment inferred ingredients already have (Heritage Orange, never Alert Red).

1Where it starts, and when it is absent

“Check the source again” sits with the other recipe actions. It appears only when the recipe has a source URL — a recipe captured from a photo has nothing to return to, so the affordance is not disabled, it simply is not there. A disabled button invites a click and then explains why it cannot help; an absent one asks no question.

3An inferred time, marked

The three fields stop being blank. Where the source states a time it is used as written and looks like any other value. Where the model worked it out, it says so, in exactly the treatment RecipeFormModal already uses for an inferred ingredient (text-primary-500 dark:text-accent-lift, Heritage Orange because this is a “worth a look”, not an error).

Why marked, not silent

The extraction prompt already forbids guessing a time, and that rule is what stops the model inventing ingredient quantities. Rather than weaken it, this gives prep, cook and servings the same escape hatch ingredients and steps already have: infer if you must, but declare it. A marked value the user can correct beats an empty field they have to research.

Choosing the review step

 A · Re-seeded edit formB · Compare, then choose
Build cost Lowest. Reuses RecipeFormModal and the existing hint idiom; roughly a new prefill flag. A new modal, plus a diff between the stored recipe and the fresh extraction.
Protects hand edits No. The new values have already won by the time the user looks; their wording is only recoverable by cancelling the whole thing. Yes. The old value is on screen beside the new one and nothing is written until the user says so.
Answers the ask Partly. It shows what changed, but not what it changed from. Fully — “show what changed and let the user accept or reject it”.
Noise Shows the whole form even when one field moved. Shows only differences; an identical re-read says so and stops.
Verdict Rejected. The single requirement this feature exists to satisfy is that a hand-edited recipe never loses edits silently, and A cannot show what would be lost. Chosen The extra modal buys the one property that matters. It also makes the no-change case honest, which A cannot express at all.
