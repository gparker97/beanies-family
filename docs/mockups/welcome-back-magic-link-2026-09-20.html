What this asserts, and what it deliberately does not

Push mode only
Neither state offers “show my code here”, because nothing is staged yet. A pull-mode code polls Drive for an approval wrap that nobody will write, and spins forever. That is the same reason the panel is excluded from the welcome gate today. Pull mode stays on the decrypt state, where a file genuinely is staged.
Scanning is an instruction, not a button
The app has no getUserMedia and no viewfinder, which is why the unreliable Open Camera button came out in 0.21.6. The steps send the reader to their own camera app, which returns through the deep link.
Desktop leads with paste, not scan
Pointing a laptop at a phone screen is absurd, so the same block reorders itself by form factor. useIsTouchPrimary() already exists and already does exactly this inside ColdSignInPanel.
Nothing was removed
Drive, saved file, different-account and the encryption note all survive, one position lower. Drive loses only its Recommended badge, which cannot stand while a different route is flagged fastest. The providers-coming-soon disclosure and the three security cards are left out of the mockup for length, not off the screen.
Colour
Heritage Orange carries the promoted block, never Alert Red, since this is a routine signal. The dark specimens use surface-raised for cards, the ink scale for copy, and accent-lift #FF8B5E for accent text, because accents get lighter on dark and never darker.

One open question. The desktop variant here leads with paste and drops the numbered steps, which is my own call rather than something you asked for. The alternative is to keep all three steps everywhere and accept that step 2 reads awkwardly on a computer. Say which you prefer and I will build that one.
