# Plan: Local Public Holidays on the Family Planner

> Date: 2026-05-12
> Related issues: None — direct implementation (per `/beanies-plan` default; full prompt log embedded below)
> Plan file (on approval, copy to): `docs/plans/2026-05-12-public-holidays-on-the-planner.md`

## User Story

As a parent using beanies.family, I want my country's public holidays to show on the Family Planner — clearly marked as special "usually no school" days, distinct from my own plans, all-day events, and trips — so I can plan childcare and trips around them at a glance.

## Context

The Family Planner today shows user-created activities (timed dots, all-day chips), travel segments, and vacation bars — but nothing tells a family "the term is interrupted here." Public holidays are high-value scheduling info (no school, many workplaces closed) that families currently track in their heads. We have no notion of a family's country anywhere yet, so this adds (a) a country-of-residence setting, (b) a committed, regenerable public-holiday dataset shipped with the app, (c) a visually distinct holiday treatment across the planner views. It stays true to the app's local-first / privacy ethos — the dataset is bundled, the country never leaves the device, nothing breaks offline.

User decisions captured during planning (see Prompt Log):

- **Data source**: generated JSON, committed to the repo (not bundling the library; not a live API).
- **Visual**: subtle warm-clay cell tint + country flag emoji by the date + an italic holiday-name chip pinned to the top of the all-day lane; week view gets a clay tint + flag on the day-header cell; day view gets a small banner.
- **Setup surface**: a new "Country & Holidays" card in Settings **and** an optional country picker in onboarding step 1 (next to the currency picker).
- **Scope**: lean v1 — national-level holidays of `type === 'public'` only, English names (a localized name appears in the details popup where the dataset has one). Regional/state granularity, `bank`/`school` days, and translated holiday names are explicit future enhancements.
- **Details popup + opt-out toggle**: yes to both. The observance note uses beanie-friendly casual phrasing — "work and school are probably off — please check!" — not a stiff "schools and many workplaces are closed."

## Requirements

1. The family can set / change / clear their **country of residence** (ISO 3166-1 alpha-2). Captured optionally during onboarding (step 1, alongside currency); editable any time in Settings.
2. When a country is set, that country's **national public holidays** appear on the Family Planner — monthly grid, weekly view, daily view, mobile day timeline, the "next 30 days" sidebar, and the day-agenda drawer.
3. Holidays are **read-only reference data** — never stored as activities, never editable/deletable. Deleting a real activity that falls on a holiday doesn't touch the holiday marker.
4. Visual treatment is distinct from normal plans, all-day events, and vacation/travel: a subtle **warm-clay cell tint**, the **country flag emoji** near the date number, and an **italic holiday-name chip** at the top of the all-day lane. Week view: clay tint + flag on the day-header cell. Day view / mobile timeline / agenda drawer: a clay-tinted **banner** ("🇸🇬 Vesak Day — public holiday").
5. Clicking a holiday opens a small **read-only details popup**: flag, name (+ localized name where available), date, country, the beanie-voiced observance note ("work and school are probably off — please check!"), and "this is just reference info — it doesn't add anything to your calendar."
6. A per-family **"Show public holidays on the planner" toggle** lets a family hide holidays without forgetting their country. Defaults on once a country is set; disabled (with helper text) when no country is set.
7. The dataset is **generated by a committed script** from the `date-holidays` package (dev-only dependency), emitting one small JSON per country to `public/holidays/<ISO2>.json`, covering `[currentYear-1 .. currentYear+3]`. The client fetches only its country's file on demand and caches it in IndexedDB with a 7-day TTL. A scheduled CI job (and `date-holidays` Dependabot bumps) keeps the committed data fresh.
8. Every failure mode degrades gracefully and is logged — never silent (see § Error Handling). Country unset → feature fully dormant, zero UI change, no fetch.
9. All new user-visible text goes through `uiStrings.ts` (`en` + `beanie` values); holiday names themselves are data (English display; localized name shown alongside in the popup when present).
10. A Help Center article covers turning the feature on, what it looks like, changing/clearing the country, the toggle, and the gotchas.

## Architecture & maintainability notes

- **Layering / dependency edges** (all one-way, no cycles): `holidayStore → settingsStore` (read `country` + `showPublicHolidays`) and `holidayStore → services/referenceData/holidays → services/indexeddb/referenceDataCacheRepository`. `HolidayChip → AllDayChip`, `HolidayChip → constants/countries`. `AllDayActivityChip → AllDayChip` (+ existing `→ stores/activityStore` for `getActivityColor`). `utils/resetStores → all stores`. The calendar views depend only on `holidayStore` (the public `holidaysInRange` / `holidayForDate`) + `HolidayChip` / `HolidayBanner` / `HolidayDetailsModal` — they never touch the loader, the cache, or the constants directly.
- **The holiday store self-loads.** Its setup body installs two `watch`es once (created at first `useHolidayStore()`): `watch(() => useSettingsStore().country, c => loadHolidaysForCountry(c), { immediate: true })` and `watch(useOnline().isOnline, online => { if (online && loadFailed.value) loadHolidaysForCountry(useSettingsStore().country) })`. Consumers just call `holidaysInRange(...)` and the data is there — no "did the right page mount the loader" footgun (matters for the deferred Nook surface and any future consumer). `resetState()` clears the data refs but does **not** tear down the watchers (on family-switch the new family's `country` re-fires the load).
- **No deep template ternaries.** `CalendarGrid.vue`'s cell-background logic moves out of a 4-way nested `:class` ternary into a small `cellBgClass(cell): string` function with early returns (vacation → clay → today-row → hover). Same for any other ≥3-branch styling choice introduced here.
- **The generic chip must not rot into a prop bag.** `AllDayChip`'s v1 props are `title, color, bgColor, leadingEmoji?, italic?, isStart, isEnd` + a `default` slot. Resist adding variant props later — if a third use needs something structurally different, reconsider the abstraction rather than bolt on.
- **Single place for future visual changes.** All holiday rendering lives in `AllDayChip` (the bar shape), `HolidayChip` (clay vars + flag), `HolidayBanner` (the banner shape), and `HolidayDetailsModal` (the popup). The 6 calendar-view touch points only do the 2-line `holidaysInRange(...)` query + drop in one of those components — the logic is not duplicated, only the wiring (intrinsic to "show holidays everywhere holidays belong").
- **Standing maintenance obligation:** the committed dataset window is `[currentYear-1 .. currentYear+3]`; the scheduled CI regen job (and `date-holidays` Dependabot bumps) must keep merging or the window eventually expires. The runtime detects an expired window (`[holidays] requested year(s) outside the published window — run npm run generate:holidays`) and degrades to "no holidays that year" rather than breaking. This is the same standing obligation the airports/translations generators already carry.

## Important Notes & Caveats

- **`country` is dual-persisted** (device IndexedDB + family Automerge), like `language`/`theme`/`textSize` — so a brand-new device can resolve the country and pre-fetch holidays before the family doc syncs. Requires `country?: CountryCode` on **both** `Settings` and `GlobalSettings` (`persistDualSetting`'s constraint is `K extends keyof Settings & keyof GlobalSettings`). `showPublicHolidays` stays **family-only**. `persistDualSetting`'s error toast does `t(\`settings.${key}\`)`→ a`settings.country` uiStrings key must exist (on the list).
- **`loadHolidaysForCountry` validates the code** against `SUPPORTED_COUNTRY_CODES` (or at minimum `/^[A-Z]{2}$/`) before fetching — a corrupt `.beanpod`-edited value can't produce a weird fetch path; on failure → `console.warn('[holidays] invalid country code "<x>" — ignoring')` and treat as unset.
- **No new `text-[Xrem]` micro-labels.** `AllDayChip`/`HolidayChip` use `text-xs` (same lane, same height budget). The flag is an emoji at default size, in its own `<span aria-hidden="true">` so screen readers don't say "flag of Singapore" before the date.
- **Cell-tint precedence** (see `cellBgClass`): a day that's both a vacation day and a holiday → vacation tint wins the cell bg; the holiday still surfaces via the corner flag + the `HolidayChip` at the top of the all-day lane. On _today_ that's also a holiday: the orange "today" gradient day-number pill still wins; the flag sits in the cell's top-right corner.
- **`ALL_DAY_VISIBLE_CAP` is 2.** Show all holidays (≤2 in practice) first, then `slice(0, max(0, CAP - holidays.length))` of `allDayItems`; the `+N` overflow counts the combined remainder and still opens the day-detail surface.
- **v1 keeps `public`-type holidays only**, national set only (a bare `new Holidays('SG')`). `bank`-only days dilute the signal; `school` is region-specific/incomplete; regional granularity (`new Holidays('US','CA')`) needs a second settings field + dependent picker — out of scope, noted in the help article.
- **Holidays are date-strings only** (`YYYY-MM-DD`) — no time math, timezone/DST-agnostic. Multi-day holidays (e.g. Chinese New Year) get a `date` + `endDate`; the runtime expansion clamps a span to a sane max (e.g. 31 days) so a corrupt `endDate` can't generate thousands of occurrences, and treats `endDate < date` as single-day with a `console.warn` (mirrors `computeAllDaySpans`'s defensive style).
- **`updateTranslations.mjs` is unaffected** — it only parses the `STRING_DEFS` block in `uiStrings.ts`; holiday names aren't there, so `zh.json` doesn't bloat.
- **Generator is committed-output, idempotent** — writes nothing if every emitted file is byte-identical; CI does `git diff --exit-code -- public/holidays src/constants/countries.ts` and opens a PR only on a real change.
- **No new E2E test** — ADR-007's 25-test cap; display-only reference data, not a data-loss-risk journey.

## Approach

### A. Data model & settings

- **`src/types/models.ts`** — `export type CountryCode = string; // ISO 3166-1 alpha-2, uppercase` near `CurrencyCode`/`LanguageCode`. Add to `Settings`: `country?: CountryCode; showPublicHolidays?: boolean;`. Add to `GlobalSettings`: `country?: CountryCode;`. (No `automerge.ts` change.)
- **`src/constants/countries.ts`** (new, generated by the script, committed) — `interface CountryInfo { code: CountryCode; name: string; flag: string; primaryLanguage: string /* ISO 639-1 lowercase */ }`, `export const COUNTRIES: CountryInfo[]` (alpha-sorted by name, only the codes `date-holidays` covers), `SUPPORTED_COUNTRY_CODES`, `getCountryInfo(code)`, `flagEmoji(code)` (regional-indicator math, as a fallback; the literal `flag` is stored in the constant, matching `languages.ts`).
- **`src/services/automerge/repositories/settingsRepository.ts`** — `setCountry(country: CountryCode | null) => saveSettings({ country: country ?? undefined })`; `setShowPublicHolidays(show: boolean) => saveSettings({ showPublicHolidays: show })`. `getDefaultSettings()` unchanged.
- **`src/stores/settingsStore.ts`** — getter `country = computed(() => settings.value.country ?? globalSettings.value.country ?? null)`; getter `showPublicHolidays = computed(() => country.value ? (settings.value.showPublicHolidays ?? true) : false)`; action `setCountry = (v) => persistDualSetting('country', v ?? undefined)`; action `setShowPublicHolidays(show)` mirroring `setWeekStartDay`'s try/catch/finally; export all four.
- **`src/composables/useCountryOptions.ts`** (new) — returns `ComboboxOption[]`: `COUNTRIES.map(c => ({ value: c.code, label: c.name, rich: { primary: \`${c.flag} ${c.name}\`, badge: c.code } }))`, alpha-sorted, with a leading "Not set" sentinel. Mirror `useCurrencyOptions.ts` if it exists.
- **`src/components/onboarding/OnboardingWelcome.vue`** — a `BaseCombobox` under the currency one: `:label="t('onboarding.countryQuestion')"`, `:placeholder="t('onboarding.countryPlaceholder')"`, default-selected via `navigator.language` region subtag if present (`'en-SG'` → `'SG'`), else blank; on `handleStart()`: `if (selectedCountry) await settingsStore.setCountry(selectedCountry)`. `data-testid="onboarding-country-select"`. ### B. Holiday data pipeline

- **`package.json`** — `devDependencies: "date-holidays": "^3.x"` (`npm install --save-dev date-holidays` at implementation time); `scripts: "generate:holidays": "node scripts/generateHolidays.mjs"`. Not added to `validate` (committed output; CPU-heavy) — run manually / by CI like `update-airports`.
- **`scripts/generateHolidays.mjs`** (new, modelled on `updateAirports.mjs` + `updateTranslations.mjs`):
  - For each `code` in `new Holidays().getCountries()`: `const hd = new Holidays(code); hd.setLanguages('en');` then for `year` in `[currentYear-1 .. currentYear+3]`, `hd.getHolidays(year)` → filter `type === 'public'` → derive `YYYY-MM-DD` from `start` (and `endDate` from `end` when the span > 1 day; clamp absurd spans). Second pass with `hd.setLanguages(primaryLang)` (first of `hd.getLanguages()`); if `primaryLang !== 'en'` and the localized name differs, store `name_local`.
  - **Validate its own output** (same rules the runtime applies): drop a record with a bad `date`/empty `name`/`endDate < date` with a logged warning; if a country `date-holidays` claimed has data yields zero valid records, log loudly. Wrap each country in `try/catch` → `console.error('[generateHolidays] skipping <ISO2>:', e); process.exitCode = 1` (never silently drop a country and exit 0).
  - Emit `public/holidays/<ISO2>.json`:
    ```json
    {
      "meta": {
        "country": "SG",
        "name": "Singapore",
        "generatedAt": "2026-05-12",
        "yearRange": [2025, 2029],
        "source": "date-holidays@3.x",
        "primaryLanguage": "en"
      },
      "holidays": [
        { "date": "2025-01-01", "name": "New Year's Day", "type": "public" },
        {
          "date": "2026-02-17",
          "endDate": "2026-02-18",
          "name": "Chinese New Year",
          "name_local": "农历新年",
          "type": "public"
        }
      ]
    }
    ```
    (`type` always `"public"` in v1 but kept in the shape; `endDate`/`name_local` only when applicable. **No separate `index.json` manifest** — a missing country = a 404 on the fetch; cache freshness = a 7-day TTL on the cached entry, not a manifest comparison.)
  - Regenerate `src/constants/countries.ts` from the collected `{ code, name, flag, primaryLanguage }` (one source for the country list + holiday coverage → can't drift).
  - Idempotent: write nothing if byte-identical to disk.
- **CI** — a scheduled workflow (monthly + on `date-holidays` Dependabot PRs): `npm ci && npm run generate:holidays && git diff --exit-code -- public/holidays src/constants/countries.ts`; open a PR if dirty (mirror the existing data-regeneration workflow if there's one for airports). Note in the `review-dependabot-prs` skill flow that bumping `date-holidays` should regenerate-and-commit in the same PR.
- **`src/services/indexeddb/repositories/referenceDataCacheRepository.ts`** (new, mirrors `translationCacheRepository.ts`) — IndexedDB `beanies-reference-data` v1, object store `holidays` keyed by country code, value `{ country, generatedAt, cachedAt: number, holidays: HolidayRecord[] }`. `getCachedHolidays(country)` returns the entry only if `Date.now() - cachedAt < 7 days`, else `null` (treated as a miss → re-fetch). `saveCachedHolidays(country, file)` stamps `cachedAt = Date.now()`. `clearAll()`. All ops wrapped per § Error Handling (IndexedDB-unavailable → log + degrade, never throw to the caller).
- **`src/services/referenceData/holidays.ts`** (new, mirrors `translationFiles.ts`) — types `HolidayRecord { date: string; endDate?: string; name: string; name_local?: string; type: 'public' }`, `HolidayFile { meta; holidays }`, `HolidayOccurrence { date: string; name: string; nameLocal?: string; countryCode: CountryCode }`. `fetchHolidayFile(country)`: `fetch('/holidays/${country}.json')` → `if (!res.ok) { console.info(...); return null }`; `catch` → `console.warn('[holidays] ...offline...:', e); return null`. `loadHolidays(country)`: try cache (7-day TTL via the repo); else fetch fresh → validate shape + per-record (drop malformed with a `console.warn`, never throw, clamp absurd spans) → write to cache → return; if both fail → `[]`. Year-window handling per § Error Handling.
