# Plan: Steer onboarding toward Google Drive + de-scarify the local-file modal

> Date: 2026-05-13
> Related issues: None — direct implementation. Prompt log: `docs/prompts/2026-05/2026-05-13-onboarding-storage-nudge.md`. ADR-016 is the storage-provider architecture (unchanged).

## Context

Several pilot families have started pods on a **local file** — likely because the create-pod "Save & Secure" step presented Drive and Local as two roughly co-equal cards, and the local-file warning modal (a) _opened_ by complimenting local files ("local files are great for security…") — overselling local, since both paths are AES-256 and Drive is just as private — (b) was three dense paragraphs, and (c) made "continue with local file" a co-equal primary with "back" as the only escape. We want to guide users toward Drive (and future cloud providers) without removing the local option.

Greg's decisions: Drive becomes the headline option; local is demoted to a "Prefer to store your data locally on this device?" link; the modal keeps a short caveat line; the trade-off line reads "Your data stays on this device. To share with other family members, you will need to manually share the data file."; keep a reassurance line (encrypted either way / only the people you share with can open it); modal title "Heads up — local files don't sync"; the "nudge families _already_ on a local file" idea is out of scope (a separate follow-up — `migrateStorage` already shipped). Mockup: `/tmp/beanies-storage-onboarding-mockup.html`.

`LocalFileSyncWarning.vue` is used **only** by `CreatePodView` (its doc-comment claiming `LoadPodView` too was stale; `LoadPodView` shows no such warning). The create-pod E2E (`e2e/helpers/auth.ts`) skips the storage UI via `window.__e2eCreatePod.setStep(3)` and only waits on the `loginV6.storageSectionLabel` heading _key_, so the markup change is E2E-safe (the key was kept). No new failure surface: the only new code is a one-line handler that delegates to the existing, fully-error-handled `handleChooseGoogleDriveStorage` (which surfaces failures via `driveResultError` + `showDriveResultModal` + `reportError({surface:'createPod.connectDrive'})`); the rewritten modal and restructured step are presentational; the existing local-file error path is untouched.

## Approach

- **`src/components/login/LocalFileSyncWarning.vue`** — rewritten (~70 lines). New `googleDriveAvailable: boolean` prop and `'use-google-drive'` emit (alongside `close`/`proceed`). The amber ⚠️ triangle → a 💾 in a Heritage-Orange-tinted squircle (`bg-[var(--tint-orange-8)]`); title → `t('storage.localFileWarningTitle')`. Body = three short lines (trade-off / compact caveat / 🔒 reassurance). Footer = stacked: primary "Use Google Drive instead" (`@use-google-drive`, rendered only when `googleDriveAvailable` — never a no-op button), below it a quiet `variant="ghost" size="sm"` "Use a local file" (`@proceed`); when Drive isn't available the "use a local file" button is the primary (`variant="primary" size="md"`). The old `t('action.back')` button is gone — `BaseModal`'s built-in × (already present) is the "back". Doc-comment fixed.
- **`src/components/login/CreatePodView.vue`** — Step 2 "Save & Secure": added a `driveCardState` computed (`'idle' | 'connecting' | 'connected'`). When `syncStore.isGoogleDriveAvailable`, the 2-col grid is replaced with a **full-width Google Drive hero card** (the click target → `handleChooseGoogleDriveStorage`; Heritage-Orange tinted; branched on `driveCardState`: idle = Drive icon + "Google Drive" + "Recommended" pill + `storage.driveSyncsWithFamily` benefit + `storage.connectGoogleDrive` "→" hint; connecting = `<BeanieSpinner>` + `googleDrive.connecting`; connected = green + ✓ + `googleDrive.fileCreated` / `…Subtitle`), and **below it a quiet underlined "Prefer to store your data locally on this device?" link** (`storage.preferLocal` → `handleLocalFileClick`), which becomes a green "✓ Saving to a local file on this device" (`storage.savingToLocalFile`) once local is chosen. When `!isGoogleDriveAvailable` (self-host without an OAuth proxy), the prior 2-card grid (disabled "Drive — Not configured" tile + the Local File card) is kept as the `v-else` branch. Added `handleUseDriveFromWarning() { showLocalFileWarning.value = false; void handleChooseGoogleDriveStorage(); }` and wired `:google-drive-available` + `@use-google-drive` on `<LocalFileSyncWarning>`. The "How this works" / "More providers coming soon" disclosures, the "Next" button, and all handlers/state are unchanged.
- **`src/services/translation/uiStrings.ts`** — 6 new keys (`storage.localFileWarningTitle`, `useGoogleDriveInstead`, `driveSyncsWithFamily`, `connectGoogleDrive`, `preferLocal`, `savingToLocalFile`) + 4 changed (`storage.localFileWarning`, `localFileBestOnDesktop`, `localFileWarningEncryption`, `localFileContinue` → "Use a local file"); each with `en` + `beanie`. `npm run translate` regenerated `public/translations/zh.json` (10 strings).
- **Tests** — NEW `src/components/login/__tests__/LocalFileSyncWarning.test.ts` (5 cases): renders the title + three body lines; primary button emits `use-google-drive` (Drive available); "use a local file" emits `proceed`; re-emits `close` when `BaseModal` closes; with `googleDriveAvailable:false` the Drive button isn't rendered.
- **Docs** — `CHANGELOG.md` (2026-05-13 `Changed` entry); this plan; the prompt log. No help-doc changes (the modal/step copy isn't doc-replicated; the getting-started / "Connecting Google Drive" / "Moving your pod" articles already frame Drive as the upgrade). No ADR — UI/copy.
- _(Not done — extracting Step 2 into `CreatePodStorageStep.vue` would shrink the 1192-line `CreatePodView`, but it shares a lot of wizard state, so it's a separate refactor. Considered and declined extracting a shared `<CloudStorageCard>` for `CreatePodView` + `LoadPodView` — the create-and-connect states vs. open-a-file-list states are different enough that it'd be a prop-heavy union of two designs; the card styling is already consistent via brand tokens.)_
