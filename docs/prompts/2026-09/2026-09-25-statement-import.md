## Outcome

Pre-plan complete (Notion #107 In Progress, prompt + mockup URL + plan URL written back). Mockup direction B (paired cards) with a bulk bar. Plan built through the four passes, approved, and implemented via /beanies-build-auto: validate green (8976 tests), test:lambda green, browser walk green (`scripts/design-screenshots/statement-import-capture.ts`). Two /code-review high rounds (10 + 10 findings, 19 fixed, 1 declined by design); round 2 moved "which due date a recurring row stands for" into one helper. Not committed, not deployed. See the plan's Outcome.

**Follow-up (possible duplicates):** a near-duplicate below the familiar bar (greg's two August interest credits, 15 days apart) showed no hint at all. Added a second match strength, `possible` (close amount, at most 31 days apart, plus a shared word, the same category or the same month), shown as a dashed pair card "Possibly already in beanies" that defaults to keep both; rows from an earlier import take part in this tier only; "Merge all" never reaches it; the unit allowance on "close" amounts is capped at 5%; `plan_built` and `commit_mix` log possible counts and how they were answered. Matching stays on-device (reasoning given to greg: account-dependent and recomputable, exhaustive and deterministic, no extra ledger data or paid read); an AI second opinion on only the borderline pairs is the option if telemetry shows the local tier missing real duplicates.

**Follow-up 2:** 0.16 vs 0.20 is a 20% gap, which the close-amount rule (2%, or 1 unit capped at 5%) rejected. Added rule (b) for a possible match: amount within 25% plus description similarity of at least 0.5. To keep frequent merchants from flagging across consecutive monthly statements, a row from an earlier import is a possible match only when its import period overlaps this statement's.

**Follow-up 3:** the interest row had been entered as an expense (direction mismatch), so it was never compared; with it as income, rule (b) flags it. Added an `interest` income category (Investments group). Reading overlay tiles were a fixed 64px, too narrow for "Transactions": now a rem width with padding, 2x2 on phones and one row from `sm`. Magic beans added to the Transactions page header (pill, Transactions pre-picked) and the top of the add-transaction drawer (new shared `MagicBeansQuickCard`, also used by the activity drawer); the page closes the add drawer when the review opens. Sweep fixes: share/unrecognised copy and help articles now name bank statements; per-kind noun strings (`ai.capture.noun.*`) so "reading it again as a bank statement" reads right; security help notes the per-page cost and that a statement re-read is not free; settings hint says a statement always asks the first time; kind test lists include transactions. Marketing site (pricing "coming soon", help index, pricing FAQ) left for deploy time.

**Follow-up 4:** every surface door pre-picks its kind (calendar/activity drawer `event`, travel page and trip wizard `travel`, cookbook and recipe form `recipe`, transactions/budget `transactions`; the quick-add sheet stays unpicked). Budget "Add transactions" card reordered: Import a statement, Quick add, Batch add; the import tile uses the magic-beans mark (✨ on the shimmering gradient) instead of 🏦. Medium /code-review run on the follow-up changes.

**Follow-up 5 (review closed out):** the review ran at max (the level arg was mis-passed as `medium.`; lesson logged). Stopped it and fixed its findings: familiar matches now need the dates to agree (no default merge of last month's same-amount bill); the unit allowance cap is 25% (5.00 vs 5.30 matches again); a strong match on an overlapping earlier import defaults to skip; a merge keeps an earlier import's provenance; the match period falls back to the line span; Unicode word tokens; a card payment keeps its offer over a weak possible; possible pass computes similarity lazily and tags rule (a)/(b); surface pre-picks are logged apart (`surface_hinted`, `surface_hint_overruled`) and never toast "pick not needed"; help copy for the page count and the pre-pick; 4th overlay tile stagger; no opacity on the quick card subtitle; stale docs; page test mock uses a real ref. Left as is: the add drawer closing when any statement review opens (speculative).
